# UDP v1 contract

All packets are UTF-8 JSON, at most 1200 bytes. UDP local and peer ports are 47731.
Only the configured literal IPv4/port is accepted. No authentication/encryption.
Required fields: `v:1`, `kind`, `instance` (sender UUID), `peer` (recipient UUID, empty only for initial hello), `epoch` (Mac-issued session UUID), `generation` (Mac-issued uint64 stream generation), `seq` (sender packet counter), `time_us` (sender monotonic microseconds; send time except snapshot, which uses the original state observation time).
Kinds: hello, ping, pong, prepare, start, stop, bind, events, snapshot, heartbeat.
Optional fields: `echo_us` (ping Mac send time), `recv_us` (Win ping receipt time), `window` (opaque Windows window lifetime UUID), `scope` (eligible UU foreground), `mods` (uint16 source mask), `event_seq` (latest input counter), `gap` (source capture discontinuity), `events`.
An event is `{id,time_us,window,kind,key,action,mods}`. id is a monotonic input counter for a Win process; each source event is consumed at most once. kind=key/modifier/button/wheel/motion. action=down/up/pulse/move. key is USB HID usage for keyboard/modifiers; button 1..5; wheel 1 vertical positive,2 negative,3 horizontal positive,4 negative; motion key=0. mods bits: left Ctrl=1,right Ctrl=2,left Win=4,right Win=8,left Alt=16,right Alt=32,left Shift=64,right Shift=128. No characters, coordinates, clipboard, titles or key identifiers in diagnostics/exports.
Every event in an events packet must be valid and have time_us <= the enclosing packet send time; reject the entire packet if any event violates this rule.

Windows hello/heartbeat once per second announces only instance/window/scope, never mods or events. Mac replies hello with its instance/epoch and `peer=Win instance`; Win acknowledges that epoch with hello addressed to Mac. Win only adopts an epoch from a hello targeted to itself. Mac accepts source data only from its acknowledged Win instance, current epoch and active generation. Restarts and reset mint a new Mac epoch. Keep recently retired instances/epochs from returning through delayed packets.
After 3s without accepted controller traffic, Win stops detailed sending and sends discovery hello with empty peer/epoch. Discovery does not retire the existing epoch: the same controller may recover, or a restarted Mac may reply with a new instance/epoch. Handshake acknowledgements remain addressed to the controller.
If a start for the current stopped generation arrives from the acknowledged controller, Win repeats stop so loss of the earlier stop cannot leave both peers stuck on that generation. Old identities, epochs and older generations cannot trigger this feedback.
Mac ping once per second; Win pong includes echo_us=ping.time_us, recv_us=Win receive time, time_us=Win send time. Clock offset Win->Mac = ((Mac send-Win receive)+(Mac receive-Win send))/2; RTT subtracts Win processing time. Reject inconsistent samples. Clock valid 10s, min RTT <=40000us.
Mac transport errors (including socket setup failures) and peer timeout retire the current epoch and revoke input evidence. After the old read source cancellation closes its socket, retry with 1/2/4/8s capped backoff and a fresh socket. Only an accepted hello acknowledgement resets backoff; successful UDP send alone is not connection proof. Configuration changes and shutdown invalidate pending retries. Manual mapping and keypad-plus settings survive; no cached input is replayed. Healthy same-window idle does not rebuild the transport.
Mac samples receipt time immediately after each recvfrom completes. A uniquely matched source event may map ahead of callback decision time by at most min RTT/2, the offset midpoint uncertainty. Larger future values remain invalid; Mac event timestamps must never be in the future. All other timing, pairing and source protection gates still apply.
Win prepare advertises eligible window on foreground transition or first eligible input, with no key data. Mac observing verified UU activity starts async network activity immediately. If Win is eligible, Mac increments generation and sends start with the window. Same-generation starts every100ms renew lease. Win accepts newer starts/stops only, same starts renew; never revive a stopped generation. Lease expires2500ms. Upon START Win sends recent1s/512 source events (eligible window only) then active immediate batches plus100ms full snapshots. Oversized batches split by encoded size. Recent events resend during active snapshots so dropped packets can recover. Idle sends only heartbeat. Input queues are bounded512; overflow emits gap and invalidates continuity. Pause/foreground exit/bound-window exit send stop and cease all detailed sending immediately. Win stop revokes current Mac generation; Mac then advances generation and sends controller stop. Mac inactivity2000ms stops detailed traffic. Stop never asserts modifiers released.
Mac bind announces learned window for current epoch/generation. Win stops if foreground is a different bound window; a new candidate may be prepared but not trusted. Bindings persist across idle/focus changes while the same window lives. Win assigns a fresh window UUID on CREATE/DESTROY/recycled HWND or process creation identity changes; never use numeric PID/HWND as lasting roles.

Snapshot `time_us` is the original processed event/health observation time, never the UDP send time. `event_seq` covers only input consumed by the network thread; queued newer input cannot be implied by a snapshot. Until a source state has been sampled, do not send a snapshot.
Pause/resume, foreground changes and capture overflow invalidate the processed snapshot and advance the source boundary. Queued input and health samples older than that boundary cannot reestablish a snapshot.

Matching uses per-event modifiers, not current snapshots. Canonical physical keys only; modifier matches consider all six Ctrl/Win/Alt source sides for any Command/Option/Control target class, without filtering by a prior mapping. A unique, reliable ordered down->up pair verifies the actual source-side to target class/device flag mapping. The source bit, target device bit and target aggregate bit must all agree with the action; down requires only that target side, up requires no side held in that target class. Mixed-side edges and overlapping releases cannot prove or revoke a mapping. Mapping evidence also requires source age <=500ms and source time no more than half the minimum RTT ahead of either the original Mac observation or decision time; delayed processing cannot make a previously future edge trustworthy. Mac flagsChanged is observed, never changed. Three unique non-motion pairs including an ordinary key/button establish window and relative path offset; recent8 delay median, initial consistent spread<=20000us. Bootstrap unique pairs in clock-adjusted range[-50000,+250000]us. Normal tolerance=25000us+min RTT/2. Ambiguity/gap/out-of-order/inconsistent clock skips. Inline correction only when evidence exists before callback, is<=500ms old and timing/window/mapping/local-source protections are valid. Late packets may calibrate recent lightweight Mac observations but never replay/repair events already forwarded. Retain consumed IDs independently of stream resets for source cache lifetime.
Default required mappings are left Ctrl, left Win and left Alt (3/3); right-side learning is optional. Targets may be any of the three classes, including many-to-one mappings. A verified target class can be reconstructed before all three required mappings are complete. Once all three are verified, unused target classes can also be cleared. Target device flags OR all active verified source mappings; releasing one source preserves the others. If any active source side lacks a verified mapping, preserve all three original target classes, including across legacy mouse clearing. Local held/unsynchronized classes and all classes not reconstructed enter preserve_mask.
Runtime input selection excludes Mac mouseMoved and all three mouseDragged types. Windows WM_MOUSEMOVE (including drag motion) passes directly to the next hook without payload decoding, scope checks, source IDs, queues or UDP. Buttons, wheels and keyboard events remain available for flags-only repair and matching. Pure motion does not renew detailed activity. The v1 motion kind/history matching is retained for protocol compatibility and offline tests; current applications do not produce or observe motion evidence.
Each new generation establishes its contiguous event watermark from the retained source history while preserving consumed IDs; missing IDs from an inactive prior generation do not constitute a current-stream hole. Same-generation holes still invalidate continuity. In automatic mode, a reliable conflicting target class or side revokes the learned configuration and starts fresh evidence with that edge. Source-ID and Mac-observation watermarks prevent pre-change cached edges from verifying or consuming newer evidence. Window/scope exit, capture discontinuity and peer stop revoke observed confirmed and partial mappings. Same-window idle retains confirmed mappings but clears partial evidence. The tool does not read UU settings; automatic mode discovers changes at their first reliable contradictory edge and requires re-pressing/releasing the three left keys.

Mac manual mode stores an explicit target class and device side for each left Ctrl/Win/Alt source in its preference domain. These settings survive window, source, peer and service boundaries; they never restore timing, window readiness, source continuity or right-source evidence. The same three reliable input pairs and timing protections are still required before correction. Unlearned active right sources preserve all three target classes. A reliable conflicting edge from a configured source latches a conflict, preserving all original flags for ordinary events (including unmatched/invalid events across legacy mouse correction) until the user explicitly saves settings. A right-source contradiction revokes only observed evidence; configured left relationships remain. Actual ordered down/up verification is reported separately from configuration. Saving settings revokes input calibration, advances consumed/source and observation watermarks, and rejects both source and Mac observations at or before the configuration's monotonic time boundary. Switching to automatic mode removes the manual assumptions. None of these settings alter the wire protocol or relax snapshot/history rules.

## Optional keypad plus text repair

The Mac toggle defaults on in the application and is persisted independently. The wire protocol is unchanged: Windows scan 0x4e already emits USB usage 87. When enabled, an observation of canonical usage 46 (Mac keycode 24) or 103 (keycode 81) additionally admits source usage 87 as a candidate; exact usage matching remains, including Mac keycode 69 -> 87. The merged candidate set must still be unique under all existing action, window, consumption, timing, clock and continuity gates.

Only a source 87 matched before the current callback can authorize the fixed Unicode `+` replacement on keyDown after prior window readiness. Source Ctrl/Win/Alt must all be released, original Mac Command/Option/Control flags absent, local protected classes absent, and manual mapping conflict absent. Shift and repeat keyDown retain their original flags and repeat fields. KeyUp and every physical keycode, timestamp and type remain unchanged. Late observations may calibrate but never replace characters or replay input. Toggling clears prior observation/calibration evidence and advances the configuration time boundary without restarting the network session or deleting manual mappings. Diagnostics expose only the setting, fixed outcome reason and numeric counts, never key identifiers or text.
